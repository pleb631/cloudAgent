# 单主机容量与部署验收

默认全局最多 4 个活动请求，每个执行容器 1 CPU、1 GiB 内存、256 PID；API 控制器另有 2 CPU、2 GiB、256 PID 限制。参数见根目录 `.env.example` 与 `compose.yaml`，运行时以实际 Docker inspect 为准。

容量至少预留控制器、并发执行容器、Docker/操作系统、镜像层和工作区空间。不能把每容器内存上限当作整机内存需求；没有聚合磁盘硬预算。SDK 费用预算依赖模型定价信息，也不是供应商账单硬限额。

## 上线前验证

在独立的 Linux Docker 测试主机完成：

1. `docker compose --profile image build` 和 `docker compose up -d openhands-api`。
2. `make test-docker`：真实容器健康、已有宿主文件读取/修改、SDK 工具执行、流式响应及清理。
3. 分租户目录写入验证；同租户并发得到 409，全局容量满得到 429；不能通过请求改变宿主挂载路径。
4. 断线、超时、模型失败和启动失败后的容器数量与占额回收；模拟控制器退出后重启，确认孤儿回收。
5. 核对容器 UID/GID、读写目录权限、CPU/内存/PID、挂载清单和无 Docker socket；用专用模型 Key 验证实际模型服务可达。
6. 验证备份恢复、磁盘告警、日志容量和残留容器告警，不在唯一一份生产数据上压测。

以上是验收清单，不是已执行结果。默认 SDK 测试使用脚本化模型；未开启的 Docker 测试是跳过，不表示通过。具体提交是否通过以 GitHub Actions 及目标服务器实测记录为准。

## 故障处理

健康检查失败时先看 agent-server 启动日志、容器退出状态、绑定端口和权限，不应单纯增大超时。清理失败会保留占额并重试；检查带本部署标签的容器，勿批量删除其他部署的容器。控制器永久停止时运维负责收尾。

硬磁盘隔离和默认禁网不在当前实现内；上线环境如要求这两项，应补充主机层策略并重新实测，不应直接扩容并发以掩盖容量问题。
