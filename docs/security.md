# 安全边界

## 当前措施

- 用户API Key在Agent层确定租户。请求不能指定底层sandbox ID、任意镜像、挂载、网络策略或资源配置。
- 官方OpenSandbox服务端Key保护控制面，但不提供这里的业务租户授权。该Key只进入受信任服务。
- 每个会话实例另有随机execd Token；认证服务端代理和loopback端口限制同时使用。Docker socket只给官方服务端。
- SDK创建实例时固定默认deny网络策略，官方服务端配置 `dns+nft`。只配置DNS过滤不能阻止直接IP流量。
- 业务执行容器申请CPU/内存限制，服务端配置PID限制、drop_capabilities ALL和no-new-privileges。不传用户host volumes。
- 子智能体工具与技能权限不能超过父级。模型自造工具名或默认通用子智能体调用会被拒绝。
- 文件内容/命令输出有大小限制，命令有服务端超时和外部总时限；异常文本不原样返回模型或客户端。

## 必须知道的限制

1. Docker共享宿主机内核，不能承诺抵御容器逃逸。OpenSandbox服务端拥有宿主机等价的Docker权限，是高信任组件。
2. 当前执行容器根文件系统可写；默认 `python:3.12-slim` 可能以root运行。不要沿用旧版本自建runtime的只读根或UID10001保证。
3. 官方egress sidecar需要NET_ADMIN，且不自动继承执行容器的CPU/内存/PID/cap-drop限制。它是单独的受信任基础设施。
4. `/workspace`不是安全边界。路径校验拒绝显式绝对路径与 `..`，但官方文件API无法在此集成中保证符号链接竞态安全。不要在同一实例放入越权数据或服务秘密。
5. SDK传输层在解析前限制单响应2MiB并拒绝压缩响应，过大目录直接失败；没有目录分页。没有磁盘配额、文件杀毒、完整审计或费用配额。
6. 默认一个API进程，租户会话映射/配额/锁不跨副本共享。不能直接增加workers。会话和文件是临时的，退出时尝试清理，TTL回收依赖官方服务端正常运行。
7. 客户端取消会尝试中断命令，但网络故障下不能保证即时取消。创建结果未知或Agent崩溃时，在官方服务端持续运行的前提下依赖TTL兜底；服务端故障时仍需运营者检查清理残留资源。
8. 绑定localhost不是完整的多用户宿主机安全策略。只有受信任的服务和运营者应该访问Docker宿主机、控制面和execd端口。

## 上线前

使用专用执行主机或更强的官方隔离runtime，部署TLS和真实身份系统，限制入口请求与会话容量，配置磁盘/存储/费用预算，保护并轮换所有密钥。重要文件应导出到有明确权限与保留策略的业务存储。对公网不可信代码，在完成独立安全评估前不要直接上线。

真实Docker/SDK测试只能验证测试覆盖的配置和行为，不代表证明了对抗任意恶意代码的安全隔离。

容量估算、sidecar/磁盘限制和资源耗尽处置见[单主机容量与故障处置](resource-capacity.md)。默认部署不提供覆盖执行容器、sidecar 和磁盘的聚合硬预算。
