# 安全边界与部署前检查

## 已有措施

- 外部 API 必须携带随机 API Key，服务端确定租户；请求里的用户标识不能改变身份。
- Manager 使用独立共享 Token，只在内部网络开放。API 容器没有 Docker socket。
- 只允许固定的 RPC 操作，配置只能来自运营者管理的本地目录。
- 文件路径检查包含 `..`、绝对路径、符号链接逃逸以及文件大小/输出限制。
- 执行容器使用非 root、只读根文件系统、禁网、去掉 Linux capabilities、no-new-privileges、CPU/内存/PID 限制。工作目录使用独立 named volume，不挂载宿主机文件夹。
- 模型密钥仅进入 Agent 服务，Manager Token 不进入执行容器。
- 子智能体受父工具权限约束；不能通过 task 工具获得父级未允许的工具。
- 上游错误不原样返还客户端，避免供应商错误消息泄漏配置。

## 不能保证的事

Docker 不是 VM。执行容器与宿主机共享内核。上述限制降低风险，但不能承诺抵御内核漏洞或所有容器逃逸。Docker daemon 权限通常等价于宿主机高权限，Manager 被攻破意味着更大风险。

提示词不能作为安全边界。即使配置要求“不要读取秘密”，拥有 read/execute 能力的模型仍可能被恶意文件影响，因此不要把秘密或越权数据放入工作区。子智能体与父智能体共享工作区，不是不同用户之间的隔离边界。

本地文件后端仅供开发，不执行命令，没有内核级隔离。多进程/副本模式没有分布式锁，不能直接扩大 workers 或水平复制。请求限制也不能替代网关抗 DoS 保护。

首版没有完整磁盘配额、工作区存储加密、合规审计、网络出口白名单、容器逃逸检测、租户级费用限制和文件杀毒。不要直接用于公开的匿名代码执行。

## 上线前

- 使用专用执行主机或更强的 sandbox runtime；限制 Manager 对 Docker 的控制面。
- 所有 Token 使用密码学随机值，定期轮换；`.env` 不提交 Git，生产使用 secret store。
- API 前面加入 TLS、请求速率限制、连接/请求时限和真实身份系统。
- 根据业务需求设置模型权限、并发、迭代上限、运行超时、存储/费用配额。
- 制定工作区保留/删除策略并监控磁盘。删除 volume 会永久删除对应工作区。
- 验证容器镜像来源、依赖锁文件和漏洞，保持宿主机内核更新。
- 运行真实 Docker 集成测试和真实模型 smoke test，再开放访问。
