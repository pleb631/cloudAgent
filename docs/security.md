# OpenHands 安全边界

本服务面向受信任用户的服务器文件任务，不是敌对租户的任意代码执行平台。

## 已实现的保护

- Bearer API Key 映射租户，客户端 `user` 不参与鉴权；宿主路径只能由服务端配置。
- 拒绝符号链接租户根、相同或嵌套租户目录；执行容器只挂载单个租户工作区。
- 单租户串行、全局并发限制、请求大小/输出大小限制、运行超时和断线取消。
- 执行容器 CPU、内存和 PID 限额；取消/结束后删除容器，清理失败保留占额并重试。
- 固定版本的官方 SDK 和服务端策略入口；受信任 YAML 控制工具、技能和叶子子智能体，禁用默认项目插件发现。

配置措施不等同于已经通过目标服务器验收；实际容器行为须运行 Docker 集成测试确认。

## 必须接受的限制

- Docker 共享宿主内核。工具白名单不是 shell 命令白名单，`/workspace` 不是容器内部的安全边界。
- bind mount 可改写或删除宿主文件。取消、失败、销毁容器都不回滚；部署前做好备份。
- 无硬磁盘配额、无出站拒绝策略。CPU/内存/PID 限制不能防止磁盘耗尽或数据外传。
- 模型凭据进入执行环境，容器内代码可能读取。只能使用独立、可撤销、低额度 Key。
- 控制器持有 Docker socket，等同高权限宿主控制能力。不要向执行容器挂载 socket、整个数据父目录或其他租户目录。
- 单 worker 单实例，不支持跨副本共享准入；多个部署不可同时使用相同工作区。
- 控制器被强制终止后，孤儿容器没有服务端自动 TTL；启动回收不能代替持续运维监控。

API 默认只监听 Linux 宿主机 127.0.0.1:8001。远程调用应经过有 TLS 和访问控制的代理，不能公开 Docker 控制面。
